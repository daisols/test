1. 开始前准备

1.1 数据及代码准备

要拿到的内容 里面应有什么 用途
public 文件夹或公开代码压缩包 backend、frontend、tools、environment.yml 网页与业务程序
同一版本的 private 文件夹或私有压缩包 backend、LICENSE.txt、README.md 编译算法；没有它后端不能完整运行
jiefangzha 展示数据 区域边界、24 张 TIF、24 张 PNG 启动后显示已有地图
test 离线计算数据 测试边界、24 张 SMAP、2 张土壤水分 TIF、1 个 Excel、1 个模型 运行本地计算
可用的高德地图配置 JavaScript API Key、安全密钥、允许的本机访问地址 显示卫星底图与地图控件

公开代码、私有编译文件和数据是三类不同的东西。拿到其中一类，不代表另外两类已经包含。

本手册不提供虚构的数据下载地址。请使用项目提供者给你的下载链接、移动硬盘或共享文件夹；如果缺少文件，先向提供者索取。私有仓库链接需要对方给你的 GitHub 账号授权，不能只凭链接访问。

1.2 检查电脑

  1. 点击 Windows“开始”按钮，打开“设置”。
  2. 进入“系统”→“系统信息”或“关于”。
  3. 找到“系统类型”，应是“64 位操作系统，基于 x64 的处理器”。
  4. 如果显示 ARM、32 位，或者你使用苹果电脑，这份编译算法不能直接使用，请联系提供者。

建议使用 16 GB 或更多内存，项目盘预留至少 40 GB 空间，安装软件的系统盘另留约 10 GB。这是用于本示例的准备建议，不是保证运行的最低配置。完整原始遥感处理数据可能远大于示例数据，需按提供者给出的数据包大小另留空间。

安装软件和下载依赖需要网络。Offline（离线）表示计算不用 GEE 下载影像，不表示安装、地图底图、天气查询都可以断网使用。

1.3 本手册统一使用的文件位置

为了少改命令，建议在 C 盘创建：

C:\FieldMoist\
    public\
    private\

创建方法：按键盘 Win+E 打开文件资源管理器，点击左侧“此电脑”，双击 C 盘； 在空白处右键→“新建”→“文件夹”，输入 FieldMoist 并回车。进入这个文件夹， 按照第 3 节把解压后的公开代码与私有文件分别放进去，最终形成上面的两层结构。

如果 C 盘空间不足，可以改成 D:\FieldMoist。后面的命令中凡出现 C:\FieldMoist，都改成你的实际位置。不要一部分用 C 盘、一部分用 D 盘。

建议使用简单英文路径，不要放在压缩包内部、云盘自动同步目录、U 盘或网络共享盘里直接运行。下载原文件可以来自这些地方，但运行前请复制到电脑本地磁盘。

2. 文件夹、命令窗口和输入方法

2.1 路径

C:\FieldMoist\public\backend 的意思是：打开 C 盘，再打开 FieldMoist，再打开 public，再打开 backend。

打开任意文件夹，点击窗口上方地址栏，可以粘贴一整条路径，然后按键盘 Enter（回车键）直接到达。

2.2 显示文件扩展名

文件名结尾的 .py、.tif、.pyd、.xlsx 是文件类型。Windows 有时默认隐藏它们。

  • Windows 11：文件夹窗口顶部“查看”→“显示”→勾选“文件扩展名”；同时勾选“隐藏的项目”。
  • Windows 10：“查看”选项卡→勾选“文件扩展名”和“隐藏的项目”。

后面要创建 .env 文件。一定要看见完整文件名，避免实际保存成 .env.txt。

2.3 什么是“命令”以及怎么执行

命令就是粘贴到命令窗口里、按回车执行的一行文字。本手册所有普通命令统一在 Anaconda Prompt 中运行，不是 Python 交互窗口，也不是浏览器地址栏。

安装 Miniconda 后，点击开始菜单，搜索 Anaconda Prompt。名称也可能包含 Miniconda3。选择 Anaconda Prompt，不要选择 Anaconda PowerShell Prompt；本手册的 cd /d 和 copy 按前者的命令格式编写。

操作方法：

  1. 选中文档灰色命令框中一行文字，按 Ctrl+C。
  2. 点击 Anaconda Prompt 窗口，按 Ctrl+V；旧版窗口也可右键粘贴。
  3. 按 Enter 执行。
  4. 等待结果，不要连续重复按 Enter。
  5. 如果窗口又出现类似 (FieldMoist) C:\FieldMoist\public> 的行，说明上一条命令已经结束，可以输入下一条。

只复制框内命令，不复制“``”、章节标题或窗口中的(FieldMoist) C:...>` 提示文字。命令里的标点请保持英文，不要自己改成中文引号。

启动后端和前端时是例外：窗口持续显示日志、不返回提示行是正常的，因为程序要一直运行。

3. 解压公开代码与私有文件

3.1 公开代码

  1. 如果收到 ZIP，右键→“全部解压缩”，等待完成。不要只双击 ZIP 后就在里面操作。
  2. 打开解压后的文件夹。
  3. 找到同时含有 backend、frontend、tools 和 environment.yml 的那一层。
  4. 将这一层文件夹命名为 public，放在 C:\FieldMoist 中。
  5. 在文件夹地址栏输入 C:\FieldMoist\public，确认直接看得到 environment.yml。

正确结构：

C:\FieldMoist\public\environment.yml
C:\FieldMoist\public\backend\manage.py
C:\FieldMoist\public\frontend\package.json
C:\FieldMoist\public\tools\install_core.py

常见错误是多了一层：C:\FieldMoist\public\public\backend 或 public\FieldMoist-main\backend。出现这种情况，把里面的内容移到正确的一层。

3.2 私有编译文件

同样解压私有压缩包，找到包含 backend 与 LICENSE.txt 的那一层，命名为 private，放在 C:\FieldMoist 中。

你应该能找到：

C:\FieldMoist\private\LICENSE.txt
C:\FieldMoist\private\backend\service\transform_tif\_native\win_amd64_cp312\manifest.json

win_amd64_cp312 下应该有 function1、function2、function3、predeal 四个文件夹，以及 manifest.json。

每个目录中有 .pyd 文件和空的 __init__.py。不要双击运行 .pyd，不要把 .pyd 改成 .py，也不要修改它的名称。它们稍后由安装命令自动复制。

不要把 private 文件夹整个覆盖到 public 上，也不要把整个 backend 文件夹替换掉。

4. 安装 Miniconda 和 Node.js

如果这两个软件已经正确安装，可直接检查版本。无需重复安装 Anaconda、Miniconda 和单独的 Python。

4.1 安装 Miniconda

  1. 在浏览器打开官方页面：https://www.anaconda.com/docs/getting-started/miniconda/install。
  2. 选择 Windows 的 64 位安装程序。不要下载 macOS、Linux 或 ARM 安装程序。
  3. 下载结束后双击安装程序。
  4. 阅读许可条款后自行决定是否接受，按安装向导继续。
  5. 选择“Just Me”（仅当前用户）通常即可；安装路径使用默认位置。
  6. 其他选项保持安装程序推荐设置。不需要手动添加 PATH，不需要更改所有系统 Python。
  7. 点击安装，等待结束，关闭安装窗口。
  8. 点击开始菜单，搜索并打开 Anaconda Prompt。
  9. 输入下面命令：
conda --version

出现 conda 加版本号表示成功。Miniconda 自带的默认 Python 即使不是 3.12 也没关系，后面会创建项目专用 Python 3.12 环境。

4.2 安装 Node.js

  1. 打开官方页面：https://nodejs.org/en/download。
  2. 选择 Windows x64 的安装程序（.msi），建议 Node.js 22 LTS，版本至少 22.12。
  3. 双击安装，按向导继续，阅读并自行接受所需协议。
  4. 保持包含 npm 的默认组件；本项目不需要勾选额外安装编译工具的选项。
  5. 安装完成后，关闭原来的 Anaconda Prompt，再重新打开一个。
  6. 分别执行：
node --version

npm --version

两条命令都应显示版本号。例如第一条显示 v22.12.0 或更高的兼容版本。不要输入 node 后直接回车，否则会进入另一种交互窗口；若误入，按 Ctrl+C 两次退出。

5. 创建 FieldMoist 环境

“环境”可以理解成项目专用的工具箱，软件会按清单把 Python 和依赖装进去。

5.1 进入公开代码目录

打开 Anaconda Prompt，执行：

cd /d C:\FieldMoist\public

cd 是进入文件夹，/d 表示需要时同时切换盘符。窗口末尾应出现 C:\FieldMoist\public>。

接着执行：

dir environment.yml

应列出 environment.yml。如果显示找不到文件，先回到第 3 节检查解压层级，不要继续安装。

5.2 按清单创建环境

conda env create -f environment.yml

这一步会下载组件，可能需要数分钟到更长时间。只要还在下载或处理文件，就不要关窗口。若出现许可或服务条款，请阅读后自行决定是否接受；出现 [y/n] 时，确认同意操作才输入 y 并回车。

成功后通常会出现提示，告诉你用 conda activate FieldMoist 激活。然后执行：

conda activate FieldMoist

窗口左边应出现 (FieldMoist)。再检查：

python --version

必须显示 Python 3.12.x。再执行：

python -c "import platform; print(platform.machine())"

应显示 AMD64。不要看到 Python 3.13、3.14 等版本还继续，因为私有文件是专门为 3.12 编译的。

新用户用 FieldMoist。SoilMoisturePlatform 只是作者之前使用的环境名，你不需要创建这个旧环境。

如果提示环境已存在，先运行 conda activate FieldMoist 和版本检查，不要随意删除现有环境。依赖报错时将错误信息交给提供者处理。

6. 把私有算法安装到正确位置

确认窗口仍在 C:\FieldMoist\public，左侧有 (FieldMoist)。执行：

python tools/install_core.py --from-dir C:\FieldMoist\private

成功时应显示：

Windows core installed. Run python tools/smoke_native_core.py next.

若显示 The matching core is already installed.，表示同版本已装好，也可以继续。

6.2 检查算法是否装好

python tools/smoke_native_core.py

应最终出现：

说明 26 个模块能够加载，多进程测试通过。如果报错，不要试着删除或重命名 .pyd。先查看第 16 节。

7. 数据清单与完整放置位置

这一节最容易出错。所有示例数据放到 public 里面的 backend\media，不是 private，也不是 public 根目录。

本节每条相对位置都以 C:\FieldMoist\public\backend\media\ 为起点。

7.1 A 组：jiefangzha 展示必需数据

数据 数量 放置位置与文件名
展示区边界主文件 1 images\83\shp\shp.shp
展示区边界索引 1 images\83\shp\shp.shx
展示区边界属性 1 images\83\shp\shp.dbf

7.2 B 组：输入 test 后计算必需数据

数据 数量 放置位置与文件名

  • images\82\82 连续两层 82 是正确的，不要删掉其中一层。

  • 输入 test 不需要自己上传 Sentinel-1、Sentinel-2 文件，也不需要 GEE 认证。

  • 第一次测试不要混入作者以前运行产生的 process\cycles、.fusion.complete、.stage1.complete、.stage2.complete 或测试结果目录。测试任务应使用干净输入，模型文件仍需保留。

7.4 实际复制方法

  1. 解压数据包到一个临时文件夹，等待全部解压完成。
  2. 在另一个文件夹窗口打开 C:\FieldMoist\public\backend\media。
  3. 如果数据包顶层是 media，打开它，把里面的内容复制到当前 media 中。
  4. 如果数据包顶层就是 images，把 images 复制到当前 media 中。
  5. 如果数据包顶层只有 82 和 83，先在当前 media 中创建 images 文件夹，再把 82 和 83 放进去。
  6. 用上面的目录树逐级核对。

正确例子：

C:\FieldMoist\public\backend\media\images\83\shp\shp.shp

错误例子：

C:\FieldMoist\public\backend\media\media\images\83\shp\shp.shp
C:\FieldMoist\public\images\83\shp\shp.shp
C:\FieldMoist\private\backend\media\images\83\shp\shp.shp

若出现“替换已有文件”提示，先确认没有把已有项目数据或已生成结果覆盖掉。第一次安装应使用空的新项目目录。

另附的 数据逐文件清单 使用英文列名，列出每一个示例输入的名字、目标位置和当前交付基准文件大小，可以用 Excel 打开或交给提供者逐项核对。relative_media_path 是相对 media 的路径，example_destination 是示例完整位置，baseline_bytes 是当前基准字节数。大小是提供者当前版本的参考值，不是程序验证的全部条件。

当前清单共 95 个文件（包含两份建议保留的 .cpg、82 的 4 份 NASA 缓存和 83 的 5 份 NASA 缓存），总计 3,250,551,078 字节， 约 3.03 GiB。这只是展开后的示例输入，不包括环境、安装程序、计算中间文件和新结果。 因此不要只留 3 GB 空间。整个研究数据包可能另含更多文件，应以实际收到的包为准。

7.5 C 组：完整遥感处理额外数据（先不用放也能运行 test）

如果以后要从 Sentinel 等原始影像做完整处理，还需要下列提供者配套文件。它们不是第一次查看展示与运行 test 的前置条件。

额外文件 放在 media 下的位置
LAI 模型 model\model_LAI.pkl
ALA 模型 model\model_ALA.pkl
CWC 模型 model\model_CWC.pkl
AIEM-Dobson 模型 model\AIEM_Dobson.pkl
粗分辨率辅助栅格 mask_tif\coarse.tif
黏粒栅格 Clay_Sand_RongZhong_tifs\Clay.tif
砂粒栅格 Clay_Sand_RongZhong_tifs\Sand.tif

这些栅格可能很大，且覆盖区域、坐标系和模型版本需要匹配。不要因为程序缺文件而自行创建同名空文件。也不要认为通过 GEE 认证就会自动下载这些本地模型。

8. 设置后端和地图配置

现在仍在 Anaconda Prompt，目录是 C:\FieldMoist\public，环境是 (FieldMoist)。

8.1 创建两个配置文件（只在第一次做）

逐条执行：

copy .env.example .env

copy frontend\.env.example frontend\.env

成功时一般显示“已复制 1 个文件”。如果问是否覆盖，表示已有配置，先选 N，不要覆盖自己已经填好的内容。

这两个文件位置不同：

  • C:\FieldMoist\public\.env：后端配置。
  • C:\FieldMoist\public\frontend\.env：网页地图配置。

8.2 编辑后端配置

执行：

notepad .env

记事本会打开文件。请保留以下本机配置：

DJANGO_DEBUG=true
DJANGO_ALLOWED_HOSTS=127.0.0.1,localhost
CORS_ALLOWED_ORIGINS=http://127.0.0.1:5173,http://localhost:5173
DB_ENGINE=sqlite

sqlite 表示系统自己创建数据库文件，不需要安装 MySQL，也不需要数据库用户名密码。

生成自己的后端随机密钥：在 Anaconda Prompt 执行下面命令，它只显示一串随机文字。

python -c "import secrets; print(secrets.token_urlsafe(48))"

复制显示出的随机文字，替换记事本中的 DJANGO_SECRET_KEY=replace-with-a-long-random-value 等号后面那一段。保留 DJANGO_SECRET_KEY=，不要改字段名，不要把窗口提示符复制进去。按 Ctrl+S 保存并关闭记事本。

先做离线示例时，不需要填写 GEE 账号；不要把注释行前的 # 随便删掉。FIELD_MOIST_MEDIA_ROOT 和 FIELDMOIST_G_* 暂时保持原有注释状态，使用默认数据位置和处理模式。

8.3 编辑高德地图配置

执行：

notepad frontend\.env

内容形如：

VITE_API_BASE_URL=http://127.0.0.1:8000/
VITE_AMAP_KEY=这里替换为实际的JavaScript_API_Key
VITE_AMAP_SECURITY_CODE=这里替换为对应安全密钥

第二、三行中文只是说明，不能原样填进去。向提供者索取可用于你电脑的配置，或登录高德开放平台 https://lbs.amap.com/，进入控制台的应用管理创建应用，添加“Web端（JS API）”类型 Key，再取得该 Key 对应的安全密钥。平台界面可能调整，以控制台实际名称为准。

如控制台要求填写允许的访问域名或来源，应允许本机访问的 localhost 和 127.0.0.1，涉及端口的来源使用本手册的 5173。不确定平台字段格式时，请让提供者按平台要求配置。

不要拿“Web服务 API”或手机 App 类型的 Key 代替 JavaScript API Key。没有正确地图凭据，计算可能仍可运行，但不能承诺出现完整的高德底图和地图展示。

按 Ctrl+S 保存。由于我们是在打开现有文件，不需要“另存为”。回到文件夹确认名称确实是 .env，而不是 .env.txt。

9. 检查数据并初始化数据库

9.1 检查数据文件

python backend/manage.py validate_fieldmoist_data --dataset all

成功时应显示：

all dataset validation passed.

这条命令是初步检查：当前版本主要检查目录存在、部分文件存在和数量下限，不会逐个保证所有日期、Excel 内容、模型兼容性都正确。因此，显示通过后仍需核对第 7 节清单并完成真实 test。

如报 missing、expected、found，分别可以理解为“缺失”“应有”“实际找到”。按提示检查路径和数据包，修复后再运行同一条命令。

9.2 创建数据库表

python backend/manage.py migrate

第一次运行会显示很多行 Applying ... OK，这是正常的。程序会在 public\backend 自动生成 db.sqlite3，不要自己从别的项目复制数据库过来。

9.3 注册 jiefangzha 展示数据

python backend/manage.py seed_fieldmoist

成功时会看到：

FieldMoist dataset registered: polygon 83, result set 83, 2018-05-01 to 2018-05-24.

这一步只是把已经放好的数据登记进数据库，不负责下载数据，也不负责生成缺少的 24 张影像。

它要求展示目录恰好有 24 个 TIF 和 24 个 PNG；如果多放了其他日期或重复 TIF，可能失败。不要用 --skip-file-check 绕过问题。

此命令用于首次安装。之后日常启动不要反复运行。 当前版本还会清理 jiefangzha（编号 83）下除示例结果 83 外的其他结果记录；如果你后来在该区新建过任务，不应随意重新初始化。不要删除数据库来解决普通启动问题。

9.4 检查后端配置

python backend/manage.py check

应显示 System check identified no issues。到了这里，私有算法、数据库和基本配置均已具备。

10. 安装网页所需组件

第一次安装时，在同一个窗口逐条执行：

npm ci --prefix frontend

等待依赖下载完成。这一步会自动创建 frontend\node_modules。不要自己从网上随意下载 node_modules 压缩包覆盖。

然后执行：

npm run build --prefix frontend

出现 built in ... 表示网页构建成功。已有的“Some chunks are larger than 500 kB”是文件体积提示，如果最后明确构建成功，不属于启动失败。

安装命令可能提示存在依赖漏洞或更新版本。不要直接执行网上建议的 npm audit fix --force，它可能改变配套版本；将提示交给维护者处理。

11. 启动后端、前端并打开网页

需要同时开着两个 Anaconda Prompt 窗口，再打开浏览器。两个命令窗口都不能在使用时关掉。

11.1 窗口一：后端

打开一个 Anaconda Prompt，逐条执行：

cd /d C:\FieldMoist\public

conda activate FieldMoist

python backend/manage.py runserver 127.0.0.1:8000 --noreload

看到类似下面文字后，保持这个窗口开着：

Starting development server at http://127.0.0.1:8000/

--noreload 是本手册采用的启动参数，避免文件变化导致后台任务随开发服务器重启。Django 提示“development server”是正常提示；本手册只用于你自己电脑运行，不用于直接架设公网服务。

检查后端是否可连接：打开 Edge 或 Chrome，在最上面的地址栏输入：

http://127.0.0.1:8000/api/health/

显示包含 FieldMoist API 和 ok 的文字即可。这不是主页面，看起来像一段数据是正常的。

11.2 窗口二：前端网页

再次从开始菜单打开一个新的 Anaconda Prompt，不要停止窗口一。

逐条执行：

cd /d C:\FieldMoist\public

conda activate FieldMoist

npm run dev --prefix frontend -- --host 127.0.0.1 --port 5173 --strictPort

看到类似：

Local: http://127.0.0.1:5173/

保持这个窗口开着。--strictPort 可以避免 5173 被占用时偷偷换到另一个端口，导致配置不匹配。

11.3 打开真正的网页

在浏览器地址栏输入：

http://127.0.0.1:5173/

按 Enter。注意是 http，不是 https；端口是 5173，不是 8000；地址要输进地址栏而不是网页中的搜索框。

可以按 Ctrl+D 添加浏览器书签，方便下次打开。但书签不会替你启动后端和前端，两个命令窗口仍需先运行。

12. 确认 jiefangzha 展示正常

第一次加载地图和影像可能需要稍等。正常时应看到：

  1. 顶部显示 FieldMoist，右侧状态是 API connected（后端已连接）。
  2. 当前页是 Explore，研究区名字为 jiefangzha。
  3. 主地图上有区域范围内的红、白、蓝土壤水分影像，高德卫星底图可见。
  4. 右侧日期从 2018-05-01 开始，可以点向右箭头切换到次日。
  5. 底部显示 Dataset ID 83、24 daily products。
  6. 色标范围是 0.00 到 0.40 m³/m³。
  7. 点击 Download GeoTIFF 会下载当前日期的栅格，一般出现在 Windows“下载”文件夹。

Satellite 是卫星底图，Standard 是标准底图；切换它们不改变土壤水分数据。

如果右侧有日期和 24 天数据，但底图空白，先检查网络与高德 Key。若显示 0 daily products，优先检查数据目录、初始化命令和后端窗口的错误信息。

13. 输入 test，完成离线计算

13.1 操作步骤

  1. 确认第 12 节展示正常。
  2. 点击顶部 Generate（生成）进入处理页面。
  3. 在 Processing mode（处理模式）里点击 Offline（离线）。
  4. 点击 Area name（区域名称）输入框，输入小写英文 test，不要加引号。
  5. 点击输入框外空白处，等预设加载完成。
  6. 系统会自动填入研究区边界、日期和本地文件路径。日期应为 2018-05-01 至 2018-05-24。
  7. 看到 Offline test dataset is ready. Click Start generation.（离线测试数据已准备好）后，点击 Start generation（开始处理）。
  8. 保持两个命令窗口开着，等待进度到 Completed（完成）和 100%。
  9. 点击 View generated result（查看生成结果），检查新生成的测试区地图。

不要再手动上传 SMAP、Sentinel、边界或 Excel；test 预设会读取你放在固定位置的那一套输入。 不要修改自动填入的日期，也不要把区域 82 改成 83。

13.2 计算时哪些现象是正常的

  • 后端窗口每个阶段只显示一行简短提示，例如“预处理影像”“计算土壤水分”“生成彩色产品”。计算细节和逐文件进度条不显示，一段时间没有新文字是正常的。
  • 电脑风扇转快、CPU 和内存使用增加。
  • 网页进度会阶段性跳变，不一定每秒增加。
  • 本机已有测试用时约 160 秒，只供参考。

计算期间不要让电脑休眠、关机，不要关闭后端窗口，不要同时重复提交多个 test。页面仍显示处理中时请耐心等待，不要仅凭后端暂时没有新文字判断程序卡住。

13.3 结果自动保存在哪里

标准全新安装的 test 输出是：

C:\FieldMoist\public\backend\media\images\82\2018-05-01_2018-05-24\soil_moisture_result\
C:\FieldMoist\public\backend\media\images\82\2018-05-01_2018-05-24\soil_moisture_png\

前一个文件夹应有 24 个逐日 .tif，后一个应有 24 个 .png。相邻的 process 中会生成中间结果，不需要手动移动它们。

默认不再生成 ml_patch_report.xlsx（像元替换对照报告）。输入用的测站 Excel 仍然必需；没有输出报告不代表缺少计算步骤。高德底图不可用时，仍可在本地彩色 PNG 上启用点分析并点击选点，圆圈显示在彩色产品上方。

若数据库来自别处、编号被占用或运行过其他项目，路径可能不再符合这份首次安装示例，应使用全新公开代码和新建数据库来复现，不要手工改数据库编号。

13.4 想再跑一次怎么办

每次启动 test 都从原始输入重新计算，包括第一次启动、失败重试和 Run test again（重新运行测试）。程序先清理预处理副本、周期缓存、完成标记和旧 TIF/PNG，保留原始 SMAP、土壤水分输入、Excel、SHP、共享模型及 NASA 缓存。不会复用已裁剪结果进行像元替换。要保留旧结果，先在计算停止时把结果复制到项目外的备份目录。其他项目的断点续算策略不变。

更新旧版本时，先停止后端，再覆盖公开程序文件和配套私有文件。在 public 目录、激活 FieldMoist 环境后运行 python tools/install_core.py --from-dir ../private --upgrade 安装新版核心，再运行 python tools/smoke_native_core.py 检查，然后重启前后端。使用构建后的前端时，还需重新运行 npm run build --prefix frontend。无需删除数据库，也无需重新执行 seed_fieldmoist。

不要通过删除 db.sqlite3、删除 images\82 或删掉共享模型来“重置”。这些操作会丢数据或导致测试无法运行。

14. 关闭软件和下次重新打开

14.1 正常关闭

  3. 点击后端命令窗口，按 Ctrl+C。
  4. 关闭两个命令窗口，再关闭浏览器即可。

14.2 第二天开机以后

不需要重新下载文件，不需要重新创建环境，不需要重新安装算法，不需要每天执行 migrate 或 seed。

窗口一：

cd /d C:\FieldMoist\public

python backend/manage.py runserver 127.0.0.1:8000 --noreload

窗口二：

在没有计算任务、后端停止时，备份自己的 backend\db.sqlite3、backend\media 和本机配置。备份应放在项目外的安全位置，不要上传到公开仓库。

15. 可选：首次 GEE 认证和在线处理

如果你的目的只是显示 jiefangzha 和运行离线 test，这一整节可以先跳过。

15.1 在线模式另外需要什么

  • 可以使用 Earth Engine 的 Google 账号。
  • 自己有权限的 Google Cloud 项目 ID；对应项目需要已启用 Earth Engine，并满足平台要求的注册、验证或计费条件。
  • 能连接 GEE 认证页面和服务端接口的网络。
  • 第 7.5 节的本地模型、辅助栅格，以及与你的区域匹配的处理数据。

账号开通和项目权限由平台及项目管理员管理。若不熟悉，请让提供者协助准备，不要把作者之前脚本中的个人项目 ID 当作通用配置。

15.2 填入自己的 GEE 项目 ID

回到 Anaconda Prompt：

cd /d C:\FieldMoist\public
conda activate FieldMoist
notepad .env

找到 EARTH_ENGINE_PROJECT=your-google-cloud-project-id，把等号后换成你的项目 ID。不是邮箱，不是项目显示名称，不是项目数字编号。

保存并关闭记事本。其他服务账号配置保持注释即可；本节使用个人浏览器交互认证方式。

15.3 执行首次认证

python tools/authorize_earth_engine.py

这是本项目提供的首次认证入口，对应旧项目 authorize.py 的认证、初始化流程；不需要寻找旧项目目录，也不需要编辑 Python 代码。

  1. 命令可能打开浏览器，或显示一个需要你打开的网址。
  2. 用有 Earth Engine 和项目权限的 Google 账号登录。
  3. 按 Google 页面及命令窗口提示完成授权；界面和验证方式可能随平台更新变化。
  4. 如果提示验证码、回调或选择项目，按实际提示操作，不要把验证码或登录信息发给别人。
  5. 最后命令窗口应显示 Google Earth Engine authentication succeeded.。

认证信息保存在当前 Windows 用户的本机账户环境中。不是每次启动都要认证；换电脑、换 Windows 用户、凭据失效或权限变更时可能需要重新认证。

**请注意网络环境。本机 Edge 能打开普通网页不代表后端 Python 能访问 GEE。应使用符合你所在机构要求、能够到达 GEE 的网络；文档不要求关闭防火墙或安装来历不明的网络工具。

15.4 在线开始前

修改 .env 后，停止并重新启动后端。打开 Generate，选 Online。区域名称使用你自己的名字，例如 my-field；不要把离线示例 test 当作在线快捷键。

在线任务需要定义边界和日期，并下载远程影像。认证成功只说明认证初始化通过，不保证每个地区、日期都有可用数据，也不保证本地辅助文件齐全。

先成功完成离线示例，再在维护者指导下运行在线处理。网络不通时不要反复点击开始；检查后端错误，优先确认网络、项目权限及本地模型。

16. 常见问题与处理办法

16.1 “不是内部或外部命令”：conda、node、npm

若是 conda，确认打开的是安装 Miniconda 后提供的 Anaconda Prompt；关闭窗口再从开始菜单重新打开。

若是 node 或 npm，确认 Node.js 已装好；安装后需要重新打开命令窗口。不要在 Python 的 >>> 窗口中执行。

16.2 出现 >>> 而不是文件夹路径

你进入了 Python 交互模式。输入 exit() 并回车，回到带文件夹路径的提示行后再执行手册命令。

16.3 提示 environment.yml 或 manage.py 找不到

重新执行 cd /d C:\FieldMoist\public，检查该目录里有没有 environment.yml，有没有 backend\manage.py。常见原因是 ZIP 多包了一层目录。

16.4 PowerShell 报错 cd /d 或 copy

本手册统一用 Anaconda Prompt（CMD 风格），不是 PowerShell。关闭当前窗口，从开始菜单选正确的 Anaconda Prompt。无需因此修改系统执行策略。

16.5 环境下载很慢、Conda 或 npm 下载失败

先检查网络、磁盘空间和错误信息。慢不等于失败，不要一见长时间等待就强制关闭。确实出现下载错误时保留末尾完整信息，请维护者检查；不要随意混用镜像地址、pip GDAL 或强制升级依赖。

16.6 Private FieldMoist core is missing 或 manifest.json 找不到

说明私有算法未正确安装。检查 C:\FieldMoist\private 里是否直接有 LICENSE.txt 和 backend，再执行第 6 节安装命令。

确认最终位置是 public\backend\service\transform_tif\_native\win_amd64_cp312，不是 private\private，也不是 public\backend\backend。

16.7 DLL load failed、Invalid native artifact 或导入模块失败

先检查 Python 3.12、Windows x64，再确认公私文件是同一版本且下载完整。校验失败可能表示文件损坏或版本不匹配，重新向提供者索取原包，不要修改 manifest.json 里的校验值。

如果系统安全软件隔离了文件，先核实来源并联系提供者，不要直接关闭安全软件。若本机仍缺运行库，按维护者建议从微软官方来源安装，不要从随机网站下载单个 DLL。

16.8 A different core version is installed

已装算法与新提供的版本不同。不要把新旧 .pyd 混在一个目录。保留旧项目备份，在新文件夹放入相互匹配的 public/private，再按手册安装。

16.9 缺少边界、影像、Excel 或共享模型

按第 7 节逐个检查。最常见的是漏了一层 images，多了一层 media，或把 82\82 合成一层。不要随便改 82/83 编号。

16.10 提示已有任务正在运行，或者一直停在处理中

先看网页的任务状态；后台现在只显示简短阶段提示，长时间没有新日志不等于停止运行。正在运行时不要重复提交。如果之前意外关机或关闭后端，状态可能残留；提供任务编号和错误信息给维护者，不要自行删数据库。

16.11 Port 5173 is already in use 或 8000 端口被占用

可能已开了一套系统。寻找之前的两个命令窗口，如果是自己的旧任务且已结束，按 Ctrl+C 停止；然后重新启动一套。

如果占用端口的是不认识的软件，不要随意结束进程。请维护者处理。不要只把网页端口改成 5174 而不改相关配置，否则可能出现跨域错误。

16.12 网页打不开或显示无法访问此网站

确认后端、前端两个窗口都在运行。前端应显示 5173 地址。访问 http://127.0.0.1:5173/，不要输入 https://、不要在浏览器直接打开 frontend\index.html。

16.13 API disconnected、CORS 或跨域错误

先打开 http://127.0.0.1:8000/api/health/。打不开说明后端未启动或启动失败。能打开时再检查前端 .env 中 API 地址是否为 http://127.0.0.1:8000/，后端 .env 是否允许 127.0.0.1:5173。

配置改完后，分别重启两个命令窗口里的服务，再刷新网页。

16.14 有界面但地图空白，或影像没有显示

地图底图空白时，检查高德 Key、安全密钥、允许来源和网络。数据为 0 时，检查展示数据目录及首次初始化有没有成功。不要把所有空白问题都归结为 GEE；已有 jiefangzha 展示不需要 GEE。

16.15 test 输入后没有自动填入数据

确认先选择的是 Offline，名称是英文 test，输入后点一下外面并等待。查看页面报错。后端必须运行，私有算法必须安装，82 的边界和本地数据必须齐全。

16.16 开始按钮不能点击

先确认预设加载完成、起止日期都有内容、没有另一项任务运行。已经成功的任务请使用 Run test again，而不是反复点击显示成功的按钮。

16.17 Excel 或模型兼容错误

不要把 measurements.xlsx 改成别的格式，也不要拿不同版本模型替换。把模型文件名、代码版本、私有编译包版本和完整错误交给提供者确认。

16.18 关闭网页以后计算还在运行

浏览器不是计算程序本身。只关网页不会必然停止后端任务。完成后按第 14 节关闭后端；不要在文件还写入时强制关机。

不要发送 .env 内容、Google 验证码、账号密码、完整认证链接或地图密钥。数据缺失时可以发文件名清单，不必先发几 GB 数据。
